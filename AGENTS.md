# Ajan Kuralları — bu repoda görev verilince nasıl çalışılır

## Dil & iletişim
- **Türkçe** yanıt ver.
- Varsayılan: **küçük adım + karar noktalarında danış.** Uzun otonom zincir kurma; belirsizlikte sor.
- İstisna: kullanıcı **"/loop" veya "devam et"** dediyse → iş **%100 bitene kadar DURMA** (checkpoint/onay için durma) ve **maksimum paralel ajan** (Workflow / paralel Agent fan-out) kullan. Doğrulama akışın parçası, durma sebebi değil.

## Görevi yaparken
- Substantive iş = paralelleştir (çok-dosya okuma, çok-vaka doğrulama, çok-perspektif tasarım). Aynı analizi tekrarlama; bir kez fan-out et, sentezle, uygula. Tek yazar (Edit) çakışmayı önler.
- Bir bug'ı düzeltince **aynı deseni repoda başka yerlerde tara**, bulduklarını söyle, onay al.
- İddia etmeden önce **oku/doğrula** (API, sürüm, flag, SHA, paket adı uydurma).

## Doğrulama — "bitti" demeden önce
- **Build + test + CANLI doğrulama** olmadan asla "tamamlandı/çalışıyor" deme.
- Web/görsel değişiklik → çalıştır + görsel test + kanıt (screenshot/log).
- Testler kalırsa çıktısıyla söyle; atlanan adım varsa söyle.

## Bitince
- İlk iş: **commit + push** (kimlik-taşıyan config dosyaları hariç).
- Commit/PR'a **AI atfı YOK** (co-authored-by yok, "Generated by" yok). Teslimatta AI-kalıntısı cümle/metadata yok.

## Deploy & prod güvenliği
- Varsayılan **DEV hedefli** deploy. Prod'a yalnız **açık istekle**.
- **Gerçek prod ID/kaydıyla yazma-testi YAPMA**; throwaway veri kullan.
- Private→public açmadan önce sır/PII/açık taraması zorunlu.

## Token verimliliği
- Ağır komutları `rtk` ile çalıştır (token için): `rtk git status`, `rtk git diff`, `rtk test <cmd>`, `rtk ls`, `rtk read <dosya>`, `rtk err <cmd>`.
- Değişmeyen dosyayı tekrar okuma; >100KB dosyaları atla; gereksiz özet/dolgu yazma.
